### Added
- **Authentication & Secure API Token Control Plane (`agent_manager/auth/`, `agent_manager/api/routes/auth.py`)** (#19) — Implemented JWT bearer authentication, HTTP-only secure cookie sessions, GitHub OAuth authorization with user whitelist verification (`is_user_authorized`), and constant-time API token validation for control plane endpoints. Supports local dev bypass via `AUTH_ENABLED=false` and unauthenticated HMAC webhook verification on `/api/webhooks/github`. Elevated Manifesto Pillar IV (Process Decoupling & Security) to **100.0%**.
- **Expo Push Notifications for Task Milestones & Guardrails (`push_notification_service.py`, `notifications.py`, `usePushNotifications.ts`)** (#24) — Implemented real-time push notification service dispatching alerts to mobile devices via the Expo Push API (`https://exp.host/--/api/v2/push/send`). Supports device token registration (`POST /api/notifications/register`), milestone alerts on status transitions (`in_review`, `paused` guardrails, `failed`, `done`), deep-linking navigation (`/(sessions)/[id]`), and an Expo React Native client hook (`usePushNotifications.ts`). Elevated Manifesto Pillar VII (Ubiquitous Command) to **100.0%**.
- **Workstation Bridge Daemon & Hybrid Local Runner Architecture (`agent_manager/bridge/`, `/ws/workstations`, `GET/POST /api/workstations`)** (#27) — Implemented outbound-only WebSocket bridge daemon (`WorkstationDaemon`, `WorkstationHub`, `LocalWorktreeExecutor`) connecting local developer workstations to the hosted Render cloud control plane with zero open inbound ports. Dispatches tasks to local `.worktrees/issue-<number>`, executes local `agy.exe` and runner processes, and streams real-time stdout, stderr, and execution status chunks upstream. Elevated Manifesto Pillar VII (Ubiquitous Command) from 50.0% to **80.0%**.
- **Asynchronous Long-Running Agents Architectural Specification (`docs/plans/issue_84_async_agents_plan.md`)** (#84) — Documented the complete architectural design and multi-phase implementation roadmap for autonomous async agent execution, state persistence, decoupling from HTTP lifecycles, background worker queues, and event dispatchers.
- **Expo Cross-Platform Mobile & Web Client Scaffold (`/apps/mobile`)** (#20) — Initialized Expo SDK project in `/apps/mobile` with TypeScript, Expo Router file-based navigation (Sessions list `index.tsx`, Session detail `session/[id].tsx`, and Settings `settings.tsx`), responsive dark-mode styling aligned with the dashboard theme, and environment configuration for REST and WebSocket endpoints (`EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_WS_URL`). Elevated Manifesto Pillar VII (Ubiquitous Command) from 20.0% to **50.0%**.

- **Cross-Repository Coordinated Tasks & Contract Sync Orchestrator (`cross_repo_orchestrator.py`, `orchestration.py`)** (#94) — Implemented multi-repo task coordinator detecting API contract and data model modifications (`routes/`, `models.py`, `openapi.json`), resolving downstream repository dependency graphs (`agent-manager` ➔ `frontend`, `f1-frontend`; `full_swing_scraper` ➔ `fit-elo`), spawning linked child worktree plans, and generating mutual markdown PR cross-references with atomic contract synchronization verification. Exposed `GET /api/orchestration/plans`, `POST /api/orchestration/plans`, and `POST /api/orchestration/plans/{plan_id}/link`. Elevated Manifesto Pillar VI (Autonomous Swarm Concurrency) to **100.0%**.
- **Per-Repository Dollar Budgeting & Dynamic Token Arbitrage (`finops_service.py`, `finops.py`)** (#93) — Implemented FinOps budget controller with per-repository daily and monthly USD spending caps, real-time token spend evaluation, threshold gating (`NORMAL`, `ARBITRAGE`, `EXCEEDED`), and automated token arbitrage model downgrading (`apply_token_arbitrage` shifts heavy models to `gemini-2.5-flash` at 80% budget utilization). Exposed `GET /api/finops/budgets` and `POST /api/finops/budgets` endpoints and connected verification to Manifesto Pillar VI (Autonomous Swarm Concurrency), elevating Pillar VI from 20.0% to **60.0%**.
- **Autonomous SemVer Release Manager & Version Tagging Engine (`release_manager.py`)** (#98) — Implemented conventional commit analyzer detecting breaking changes, feature additions, and bug fixes to compute SemVer version bumps (`major`, `minor`, `patch`). Updates version manifests (`package.json`, etc.), formats markdown release notes with categorized bullets, and cuts annotated Git release tags (`vX.Y.Z`). Elevated Manifesto Pillar VIII (Deterministic Accountability) from 15.0% to **65.0%+**.
- **Multi-Agent Worktree Rebase & Merge Conflict Supervisor (`rebase_supervisor.py`)** (#96) — Implemented autonomous git rebase supervisor that detects upstream drift on `origin/main` before PR creation, runs non-interactive rebases inside active worktrees, detects conflicted files, automatically parses and resolves non-overlapping/additive conflict blocks (`resolve_simple_conflicts`), safely aborts (`git rebase --abort`) if semantic conflicts require human review, and force-pushes with lease (`git push --force-with-lease`). Added lightweight `/healthz` liveness and readiness probe on `server.py` verifying database connectivity. Elevated Manifesto Pillar IV to 80.0%.

Added `RepoIndexer` scanning connected workspace projects to extract API endpoints, data models, schemas, and AGENTS directives into structured chunks. Exposed `POST /api/memory/query`, `POST /api/memory/index`, and `GET /api/memory/stats` API routes, and seamlessly injected retrieved cross-repository architectural context into Stage 2 (Architect Planner) prompts in `agent_service_pipeline.py`. Elevated Manifesto Pillar III to 100.0%.
- **Autonomous Agent Replication System Prompt Blueprint (`docs/AUTONOMOUS_AGENT_SYSTEM_PROMPT.md`)** — Documented a comprehensive, self-contained single-prompt markdown blueprint establishing the 8-pillar autonomous agent execution model (worktree enclaves, takeover protocol, circuit breakers, anti-monolith LOC limits, command suppression, cognitive stages, changelog audits, and recurring cron sweeps) for copy-paste deployment across all connected projects.

- **Alembic Migration Infrastructure (`alembic/`, `alembic.ini`)** (#18) — Configured Alembic database migrations with auto-generation support, metadata binding to `agent_sessions` and `conversation_messages`, dynamic connection routing, and initial versioned migration schema.
- **Zero-Downtime Legacy Data Auto-Migration (`migrate_json.py`)** (#18) — Added automatic migration on startup from legacy flat JSON (`data/sessions.json`) into the relational database, preserving all historical sessions, token telemetry, and conversation messages.
- **Long Generated File & Binary Asset Filter Service (`file_filter_service.py`)** (#39) — Implemented file classification and circuit breaker preventing autonomous agents and context engines from scanning, reading, or dumping bloated lockfiles (package-lock, yarn, poetry), minified assets (*.min.js, *.min.css), source maps, and binary dumps. Integrated with Manifesto Pillar III metrics.

When agents are running, it lets them proceed uninterrupted; when idle, it evaluates live Code Health and Manifesto compliance metrics, dynamically maps the highest-impact deficiency to its corresponding backlog issue (#100, #101, #39, #18, #90, etc.), and advances the task.

- **Manifesto Metric Automated Test Suite (`test_manifesto_metrics.py`)** — Comprehensive unit and integration test suite asserting quantitative threshold criteria across all eight pillars and verifying endpoint integration.

Synthesizes lessons from all completed and open issues into the 8 core pillars of autonomous agent engineering (Radical Observability, Sacred Isolation, Anti-Monolith Hygiene, Process Immortality, Cognitive Division of Labor, Autonomous Swarm Concurrency, Ubiquitous Command, Deterministic Accountability), 3-tier system topology, and multi-phase roadmap.
- **Decoupled Independent Agent Daemon Service** — Each autonomous agent now executes in its own dedicated, detached OS daemon service process (`agent_service.py` via `launch_independent_agent_service`). Agents run fully independent of the FastAPI web server lifecycle, allowing the web server and UI to be modified, updated, and restarted continuously without killing or interrupting running agents.
- **Auto-Reattaching Stream Tailer** — Added automatic process discovery and log tailer reattachment in FastAPI's `lifespan` startup hook. When the web server restarts or reloads, it discovers active agent PIDs via `is_process_alive`, resumes tailing stream JSON logs from the saved byte offset (`stream_log_offset`), and restores real-time WebSocket token streaming to the browser.
- **Atomic Single-Session Disk Persistence** — Added `save_single_session` in `storage.py` enabling independent agent daemon processes to update session state atomically in `data/sessions.json` without clobbering other concurrent agent sessions or web server writes.
- **Rich Markdown Rendering Component** — Added `MarkdownView.tsx` with full GitHub Flavored Markdown support including copyable code snippets, tables, blockquotes, and tasklist checkboxes.
- **One-Click Agent Restart Action** — Added `POST /api/issues/restart` with complete process tree termination (`taskkill /F /T`) and fresh instance instantiation.
- **Voice Issue Listener & Autonomous Task Spawner** — Added interactive voice recognition modal (`🎙️ Voice Issue`) with real-time speech transcription, AI-assisted issue structuring (acceptance criteria, overview, technical considerations), automatic GitHub Issue creation, Project Board #3 card placement, and 1-click autonomous agent assignment.
- **Voice Issue API Endpoint** — Added `/api/issues/voice-create` endpoint with intelligent repository inference from spoken text (`FitElo`, `Better Business Deal`, `Agent Manager`, `Leanfolio`, `F1 Frontend`) and automated agent spawner invocation.
- **Issue Command Center UI** — Replaced raw log terminal views with an executive Issue Command Center featuring direct issue control, repository filtering, search, status tabs, and 5-stage milestone trackers (`Worktree` ➔ `Code` ➔ `Tests` ➔ `Changelog` ➔ `PR`).
- **Algorithmic Supervisor & Agent Governance Engine** — Implemented deterministic supervisor module (`agent_manager/runners/supervisor.py`) enforcing automated GitHub takeover notices, project board status sync (`in_progress`, `in_review`), worktree boundary isolation, turn budget circuit breakers, and programmatic CHANGELOG verification.
- **Unified Issue Management API** — Consolidated endpoints into `/api/issues` (`/api/issues/start`, `/api/issues/pause`, `/api/issues/stop`, `/api/issues/sync`) for lightweight, direct issue orchestration.
- **Scheduler Pause & Resume Control** — Added manual and programmatic pause/resume controls for the autonomous cron dispatcher with UI toggle buttons in the Cron view, API endpoints (`/api/cron/pause`, `/api/cron/resume`), and persistent configuration.
- **Mandatory CHANGELOG.md Protocol & Directives** — Added Section 6 to `AGENTS.md` and injected changelog maintenance directives into agent takeover prompts, Stage 2/3 pipelines, webhooks, and interpretation services.

- **Direct GitHub Issue Creation** — Added an interactive modal in the Projects view to create issues directly into GitHub Project Board columns.
- **Multi-Repository Parallel Backlog Dispatching** — Re-architected task dispatcher to group project items per repository, preventing single-repo blocking and enabling independent agent concurrency.
